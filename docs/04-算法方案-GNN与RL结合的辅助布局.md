## 1. 问题定义

### 1.1 形式化

给定设计实例 $D = (B, C, N, S)$：
- $B$：板级信息（板框多边形、叠层、层数、单位、原点）
- $C = \{c_1, ..., c_n\}$：器件集合，每个器件有封装尺寸、高度、引脚集合、类型、功率、是否固定
- $N = \{net_1, ..., net_m\}$：网络集合，每个网络连接若干引脚，带类型与电气约束
- $S$：约束集合（禁布区、限高区、Room 定义、固定器件坐标、对称要求、结构接口位置）

求解布局 $P = \{(x_i, y_i, \theta_i, s_i)\}_{i=1}^n$，其中 $\theta_i \in \{0°, 90°, 180°, 270°\}$，$s_i \in \{Top, Bottom\}$。

目标：
$$\min_P \; \mathcal{L}(P) = w_1 \cdot \text{HPWL}(P) + w_2 \cdot \text{Cong}(P) + w_3 \cdot \text{Thermal}(P) + w_4 \cdot \text{RuleViol}(P) + w_5 \cdot \text{Aesthetic}(P)$$

约束：
$$\text{Overlap}(P) = 0, \quad P \models S_{\text{hard}}$$

### 1.2 这个问题为什么难

1. **组合爆炸**：$n$ 个器件在连续 2D 空间 + 4 种旋转 + 2 个面，搜索空间天文数字。
2. **多目标且权重未知**：$w_1 ... w_5$ 没人能给出确切值，它们隐含在工程师的经验里。
3. **强硬约束**：结构、机械、安规约束是不可协商的。
4. **小样本**：500~5000 块板，对深度学习是极小的数据量（对比：IC 布局也没有公开大数据集，但至少可以合成）。
5. **评价主观**：两个 HPWL 相近的布局，工程师可能一个说好一个说不能用。
6. **无快速仿真器**：真正的评价需要布线、SI 仿真、热仿真，太慢，无法支撑 RL 的百万次交互。

### 1.3 我们的破题思路

| 难点 | 破解手段 |
|---|---|
| 组合爆炸 | 分层分解（区 → 关键器件 → 外围器件），把大问题切成小问题 |
| 权重未知 | **逆强化学习 / 偏好学习**：从历史布局反推权重；专家 pairwise 打分 |
| 硬约束 | **动作掩码 + 合法化后处理**，从机制上保证而非靠学习 |
| 小样本 | **模仿学习为主，RL 为辅**；自监督预训练 GNN；数据增强 |
| 评价主观 | 引入专家 pairwise 比较数据，训练**布局判别器（Critic）**作为奖励模型 |
| 无仿真器 | 自研**代理评估器（Surrogate Evaluator）**：GPU 加速的 HPWL + 拥塞 + 热的快速近似 |

## 2. 图表示设计（GNN 的地基）

图建模是整个方案里最需要精心设计的部分。建模错了，后面模型再强也白搭。

### 2.1 异构图结构

采用 **器件-引脚-网络三类节点的异构图**（`HeteroData`）：

```
节点类型：
  Component（器件）    n ≈ 100 ~ 5000
  Pin（引脚）          ≈ 10 * n
  Net（网络）          m ≈ 0.5 ~ 2 * n
  Region（区域/Room）  少量

边类型（含反向边）：
  (Component, has_pin, Pin)        器件拥有引脚
  (Pin, belongs_to, Net)           引脚属于网络
  (Net, connects, Pin)             反向
  (Component, in_region, Region)   器件属于区域
  (Component, hierarchy, Component) 原理图层次关系（同一功能块）
  (Component, near, Component)     几何邻接（布局过程中动态构建，KNN）
  (Component, symmetric, Component) 对称/配对关系（差分对的匹配电阻等）
```

**为什么用 Net 作为独立节点而不是 clique 展开？**
GND 网络可能连接上千个引脚，clique 展开会产生 $10^6$ 条边，直接爆炸。星形展开（Pin → Net → Pin）把边数降到线性，且 Net 节点天然可以携带网络级特征（类型、约束、总长度预算）。这是从超图（Hypergraph）到二部图的标准转换。

**大网络处理**：对 GND / VCC 这类超大网络，特殊标记并在消息传递中降权或跳过，否则它们会成为"信息高速公路"，让所有器件的嵌入趋同（过平滑）。

### 2.2 节点特征设计

**Component 节点特征**（这是重中之重，直接决定模型上限）：

| 类别 | 特征 | 说明 |
|---|---|---|
| 几何 | 封装长、宽、面积、高度、宽高比 | 归一化到板尺寸 |
| 几何 | 引脚数、引脚密度、焊盘类型分布 | BGA / QFP / 两端器件差异大 |
| 类型 | 器件大类 one-hot（IC / 连接器 / 电阻 / 电容 / 电感 / 晶振 / 磁性件 / 散热件） | |
| 类型 | 细分角色（主控 / 存储 / 电源 IC / 电源无源件 / 去耦 / 上下拉 / 滤波 / 匹配 / ESD） | **由规则引擎+器件库+网表分析自动打标，非常关键** |
| 电气 | 额定功率、静态功耗估计、工作频率、电压域 | 来自器件库与 BOM |
| 电气 | 所连网络的类型统计（高速网络数、电源网络数、模拟网络数） | |
| 热 | 是否发热器件、热阻、是否需散热器 | |
| 约束 | 是否固定、是否限定面、限高约束值、所属 Room | |
| 拓扑 | 度、加权度、PageRank、聚类系数、到主控的最短路径 | 图论特征，便宜且有效 |
| 位置编码 | 拉普拉斯特征向量 / 随机游走编码（前 k 维） | 让 GNN 感知全局结构 |
| **动态（布局过程中）** | 当前是否已摆放、当前坐标、旋转、面 | RL 状态的一部分 |

**Pin 节点特征**：相对器件中心的偏移、焊盘尺寸、层、引脚功能（电源/地/信号/NC）。

**Net 节点特征**：引脚数、网络类型（GND/PWR/CLK/高速差分/模拟/普通）、约束（阻抗、等长、最大长度）、估计驱动强度、是否关键网络、权重。

**Region 节点特征**：面积、多边形形状描述子、限高、允许器件类型。

### 2.3 特征打标的自动化（工程量大但必须做）

器件"细分角色"的自动识别是特征质量的关键。建议规则 + 学习混合：

```
去耦电容识别：容值在 [1nF, 10uF] 且一端接 GND 网络、另一端接电源网络，
              且物理距离最近的 IC 电源引脚在阈值内
上下拉电阻：  一端接电源/地，另一端接信号网络，阻值在 [1k, 100k]
串联匹配电阻：串在高速信号路径上，阻值在 [10, 100]
主控识别：    引脚数最多 + 连接网络数最多 + 器件类型为 IC
电源模块识别：从 DC-DC IC 出发做子图扩展（电感、大电容、反馈电阻）
```

**这套"网表语义解析器"是本项目一个独立且高价值的组件**，它同时服务于规则引擎（判断规则适用对象）、图特征、以及模块划分。建议第 2 个月就开始建设。

## 3. 整体算法架构：五阶段流水线

```
┌─────────────────────────────────────────────────────────────────────────┐
│  阶段 0：预处理与模块划分                                                 │
│  网表语义解析 → 功能模块识别 → 层次分解 → 硬约束提取                       │
├─────────────────────────────────────────────────────────────────────────┤
│  阶段 1：GNN 图编码（表示学习）                                           │
│  异构 GNN 编码器 → 器件嵌入 / 模块嵌入 / 全局嵌入                          │
│  ← 自监督预训练（掩码属性预测、链接预测、对比学习）                          │
├─────────────────────────────────────────────────────────────────────────┤
│  阶段 2A：检索复用（快路径，最先落地）                                     │
│  模块图嵌入 → 向量检索历史相似模块 → 子图匹配验证 → 布局模板迁移            │
├─────────────────────────────────────────────────────────────────────────┤
│  阶段 2B：RL 序列决策（慢路径，覆盖无模板部分）                            │
│  策略网络（GNN 编码 + 动作头）→ 逐器件摆放 → 动作掩码保证合法              │
│  ← 模仿学习预训练 ← 离线 RL ← 在线 PPO 微调                               │
├─────────────────────────────────────────────────────────────────────────┤
│  阶段 3：解析式精细优化                                                   │
│  可微目标函数（HPWL 平滑近似 + 密度惩罚）→ GPU 梯度下降                    │
├─────────────────────────────────────────────────────────────────────────┤
│  阶段 4：合法化与规则修复                                                 │
│  消重叠 → 网格对齐 → 规则引擎全检 → 局部修复（CP-SAT / 局部搜索）          │
├─────────────────────────────────────────────────────────────────────────┤
│  阶段 5：评估、排序与解释                                                 │
│  多指标评估 → 学习到的判别器打分 → 候选方案排序 → 生成自然语言解释          │
└─────────────────────────────────────────────────────────────────────────┘
```

**关键设计哲学**：不要指望一个端到端模型解决所有问题。RL 负责它最擅长的部分（序列化的、组合性的、离散的高层决策），连续微调交给可微优化，硬约束交给符号方法。这是"神经-符号混合"（Neuro-Symbolic）的典型应用。

## 4. 阶段 1：GNN 编码器与自监督预训练

### 4.1 编码器结构

```
输入：HeteroData(Component, Pin, Net, Region + 各类边)
  ↓
各类节点特征 → 独立 MLP 投影到统一维度 d=256
  ↓
L 层异构消息传递（推荐 HGT 或 带边类型的 GATv2），L = 4~6
  每层：Component ← Pin ← Net ← Pin ← Component 的双向传播
  ↓
  + 残差连接 + LayerNorm + 边特征注入（GINE 风格）
  ↓
输出：
  h_component ∈ R^{n×d}     器件嵌入
  h_net ∈ R^{m×d}           网络嵌入
  h_module（模块内器件嵌入池化）
  h_global（全图池化，含 Set2Set / Attention Pooling）
```

**层数选择**：PCB 图的有效直径不大（大部分器件到主控 2~4 跳），L 取 4~6 足够。层数过多会过平滑。

### 4.2 自监督预训练（解决小样本的关键）

在没有布局标签的情况下，先用**全部**历史设计（哪怕布局质量不高）做自监督预训练，学到通用的"电路结构理解"：

| 预训练任务 | 做法 | 学到什么 |
|---|---|---|
| **掩码属性预测** | 随机遮蔽器件的类型/封装/功率，让模型预测 | 器件在电路中的角色语义 |
| **链接预测** | 遮蔽部分引脚-网络连接，预测是否相连 | 电路连接的先验模式 |
| **模块对比学习** | 同一功能模块的不同实例（不同板上的 DDR 电路）作为正样本对 | 功能模块的不变表示 |
| **相对位置预测** | 给定两个器件，预测它们在历史布局中的相对方位/距离区间 | **布局的空间先验，这个任务最贴合下游** |
| **图重构** | 图自编码器 | 全局结构 |

预训练后的编码器同时服务于：检索复用（阶段 2A）、RL 策略网络（阶段 2B）、布局判别器（阶段 5）。**一次预训练，三处受益**，这是把 GNN 与 RL 结合的第一个结构性收益点。

## 5. 阶段 2A：检索复用（建议最先交付）

### 5.1 为什么这条路要先做

- 工程师本来就是这么干的（复用旧板模块），接受度天然高
- 不依赖 RL 训练成功，**风险可控**
- 产出的"模块-布局"配对数据，正好是 RL 的训练素材
- 6 个月内**一定能出可演示成果**

### 5.2 实现路径

```
当前设计 → 模块划分 → 每个模块的子图 → GNN 编码 → 模块向量
   ↓
向量库检索（历史模块库，Top-50）
   ↓
子图同构/相似度精确验证（VF2 / 图编辑距离近似）
   ↓
可迁移性评估（器件型号是否一致、封装是否兼容、约束是否冲突）
   ↓
布局模板迁移（相对坐标映射 + 旋转对齐 + 缺失器件补位）
   ↓
局部优化 + 合法化
```

**模块划分方法**（多路并行，取并集）：
- 原理图层次结构（Allegro 支持层次化设计，最可靠）
- 历史 Room 定义（人类已经分好的区）
- 图聚类（Louvain / Leiden 社区发现，在网表图上）
- 电源域划分（同一电压域的器件）
- 语义规则（DDR 组、电源模块、时钟电路、接口电路）

**关键工程细节**：模块库的建立需要把历史板全部拆成模块并入库，这是数据工程的重头戏（见 `05-数据工程与评测体系.md`）。

## 6. 阶段 2B：强化学习决策（技术制高点）

### 6.1 MDP 建模

**状态 $s_t$**：
- 已摆放器件的位置（渲染为多通道密度图，或作为图节点的动态特征）
- 待摆放器件的图嵌入
- 当前待决策器件的嵌入
- 板面占用图（多通道 2D 网格：Top 面占用、Bottom 面占用、禁布区、限高约束图、热约束图、已布器件的引脚密度图）
- 全局进度信息

> **状态表示的双路设计**：图表示（GNN）擅长捕捉"谁和谁连着"，网格图表示（CNN）擅长捕捉"哪里还有空间"。**两者必须同时使用并融合**。MaskPlace 的经验表明，纯图表示会丢失精确的几何信息。这是 GNN 与 RL 结合的第二个结构性设计点。

**动作 $a_t$**：
- **决策顺序**：优先用固定顺序（按重要性排序：固定件 → 主控 → 电源 → 存储 → 连接器 → 外围），也可让模型学习顺序（Pointer Network）。**建议 PoC 用固定顺序，降低难度。**
- **位置**：网格化离散动作空间。板面离散成 $H \times W$ 网格（如 224×224），动作 = (网格坐标, 旋转 ∈ 4, 面 ∈ 2)。动作空间大小 $= H \times W \times 8$。
- 后续用解析式优化把网格坐标细化到连续值。

**动作掩码（Action Masking，硬约束的保证机制）**：
在每一步生成一个 $H \times W \times 8$ 的布尔掩码，标记哪些位置是合法的：
```
掩码 = 板框内 ∧ 不与已摆放器件重叠 ∧ 不在禁布区 ∧ 满足限高
       ∧ 满足面限制 ∧ 满足 Room 归属 ∧ 满足最小间距规则
```
掩码由**规则引擎**生成（架构复用点），用卷积/形态学膨胀高效计算。非法位置的 logits 置为 $-\infty$。

> 这一机制是"工程师能接受"的前提：**模型物理上不可能输出违反硬约束的方案**，而不是"学会了尽量不违反"。

**奖励 $r_t$**：
- **稠密奖励**（每步）：本步摆放导致的增量 HPWL（负值）、增量拥塞、规则软违反惩罚
- **稀疏奖励**（终局）：整体质量评分（HPWL、拥塞、热、规则违反数、判别器打分）
- **推荐**：以稠密的增量 HPWL 为主（保证学习信号稠密），终局加上综合评分

$$r_t = -\alpha \cdot \Delta\text{HPWL}_t - \beta \cdot \Delta\text{Cong}_t - \gamma \cdot \text{SoftViol}_t$$
$$r_T \mathrel{+}= -w \cdot \mathcal{L}_{\text{final}}(P) + \lambda \cdot \text{Critic}_{\text{expert}}(P)$$

其中 $\text{Critic}_{\text{expert}}$ 是从专家偏好数据学到的判别器（见 6.4）。

### 6.2 策略网络与价值网络结构

```
                 ┌──────────────────────────────────────┐
                 │ 图分支：异构 GNN 编码器（预训练权重）    │
状态 s_t ────────┤   → h_current（当前器件嵌入）           │
                 │   → h_placed（已摆放器件聚合）          ├──→ 融合
                 │   → h_global（全局）                   │    (Concat +
                 ├──────────────────────────────────────┤     Cross-Attn)
                 │ 网格分支：CNN / U-Net 编码占用图        │        │
                 │   多通道 2D 特征图 → 空间特征           │        │
                 └──────────────────────────────────────┘        │
                                                                  ↓
                          ┌───────────────────────────────────────┴──┐
                          │ 策略头：反卷积/U-Net 解码 → H×W×8 位置分布 │
                          │        （逐点与 h_current 做条件调制 FiLM） │
                          │ + 动作掩码                                │
                          └───────────────────────────────────────────┘
                          ┌──────────────────────────────────────────┐
                          │ 价值头：全局池化 → MLP → V(s)              │
                          └──────────────────────────────────────────┘
```

**GNN 与 RL 的具体结合点总结**（这是你最关心的部分）：
1. **表征结合**：GNN 提供状态编码，替代手工特征。器件"是什么、和谁连、有多重要"由 GNN 学到。
2. **泛化结合**：GNN 的置换不变性与图规模无关性，让策略能泛化到未见过的电路（不同器件数、不同拓扑），这是纯 CNN 或 MLP 做不到的。
3. **价值函数结合**：Google Nature 2021 的核心贡献之一就是用 Edge-GNN 训练一个能预测最终线长/拥塞的价值网络，作为奖励代理。我们同样需要一个 **GNN-based 布局质量预测器**。
4. **条件调制结合**：当前待摆放器件的 GNN 嵌入，通过 FiLM / Cross-Attention 调制网格分支的空间特征图，实现"针对这个器件，哪里合适"的空间注意力。
5. **迁移结合**：GNN 编码器在自监督预训练、检索复用、RL 策略、质量判别器之间共享，是把小样本数据价值最大化的手段。

### 6.3 三段式训练（务必按顺序）

#### 第一段：模仿学习 / 行为克隆（Behavior Cloning, BC）

从历史设计构造专家轨迹：
```
对每块历史板：
  按"重要性排序"重放摆放顺序（或用启发式还原一个合理顺序）
  逐步产生 (状态, 专家动作) 对
  专家动作 = 该器件在历史布局中的真实网格坐标 + 旋转 + 面
```
用交叉熵损失训练策略网络直接预测专家动作。

**这一步的价值怎么强调都不为过**：
- 它让模型直接学到人类的布局风格（包括那些说不清的"审美"）
- 它给 RL 提供了一个远好于随机的初始策略
- 即使后续 RL 失败，BC 模型本身就已经是一个可用的推荐器

**数据量估算**：5000 块板 × 平均 500 个器件 = 250 万条 (状态, 动作) 样本。对 BC 来说是相当充足的。

**轨迹顺序问题**：历史板只有最终结果，没有摆放顺序。解决方案：
- 用启发式规则生成合理顺序（重要性 + 连接紧密度）
- 数据增强：同一块板生成多个不同顺序的轨迹
- 或采用顺序无关的建模（一次性预测所有位置，类似 GraphPlanner 的 VAE 方案）

#### 第二段：离线强化学习（Offline RL）

BC 只会模仿，不会超越。用离线 RL（**IQL / CQL / Decision Transformer**）从历史数据中学习"什么样的布局更好"：
- 需要给历史布局打分（用代理评估器 + 专家标注），构造带回报的轨迹
- **ChiPFormer**（ICML 2023）的思路特别贴合我们：把布局当作序列建模问题，用 Decision Transformer 在离线数据上训练，可在新电路上快速微调
- 优势：不需要与环境大量交互，训练稳定

#### 第三段：在线 PPO 微调

有了好的初始策略后，用 PPO 在代理评估环境中在线微调：
- 环境：自研的快速布局评估器（必须 GPU 加速，目标单次评估 < 10ms）
- 加 KL 惩罚约束策略不要偏离 BC 策略太远（防止学出"HPWL 很低但人类觉得离谱"的布局）
- 用 GAE、动作掩码、多环境并行采样

$$\mathcal{L}_{PPO} = \mathcal{L}_{clip} - c_1 \mathcal{L}_{value} + c_2 \mathcal{H}[\pi] - c_3 \cdot D_{KL}(\pi \| \pi_{BC})$$

**最后那一项 KL 约束是 PCB 场景的特殊要求**：我们不是要找到理论最优布局，而是要找到"工程师会采纳的、比人类稍好的"布局。

### 6.4 奖励模型：从专家偏好中学习权重

多目标权重 $w_1...w_5$ 无法人工设定。方案：**偏好学习（类似 RLHF 的 Reward Model）**

```
1. 采集数据：给资深工程师看成对的布局方案（A vs B），让他选哪个更好
   （数据来源：历史板 vs 模型生成、不同版本的历史板、人工扰动的对照）
2. 训练判别器：GNN + CNN 编码布局 → 标量分数
   损失：Bradley-Terry 模型  L = -log σ(score(A) - score(B))
3. 该判别器作为 RL 的终局奖励项，也用于候选方案排序
```

**这是把工程师主观经验"编码"进算法的唯一可行途径**，而且标注成本可控（pairwise 比较比打绝对分容易得多，工程师 1 小时可标注 100+ 对）。

建议标注量：**PoC 阶段 3000~5000 对**，由 2~3 位资深工程师完成，配合一致性检验。

### 6.5 代理评估器（RL 环境的性能核心）

RL 训练需要百万次评估，必须极快。设计如下：

| 指标 | 快速近似方法 | 目标耗时 |
|---|---|---|
| HPWL | 每个 Net 的引脚包围盒，向量化 GPU 计算；增量更新 | < 1ms |
| 拥塞 | RUDY（网格化线密度估计）或 2 层快速全局布线 | < 5ms |
| 重叠 | 空间哈希 / GPU 网格光栅化 | < 1ms |
| 热分布 | 功率密度卷积（高斯核）近似扩散 | < 2ms |
| 规则违反 | 规则引擎的向量化子集（只跑几何类规则） | < 10ms |
| 对称/对齐 | 统计量 | < 1ms |

**校准**：代理评估器必须与真实评估（实际布线后的线长、真实 DRC、热仿真）做相关性校准，抽样 100 块板做回归分析，相关系数目标 > 0.8。**不校准的代理评估器会让 RL 学出"刷分但没用"的布局，这是最常见的失败模式。**

## 7. 阶段 3：解析式精细优化

RL 输出的是网格级离散位置，需要连续化精修。借鉴 **DREAMPlace** 的思路：

把布局目标写成可微函数，用 PyTorch 在 GPU 上做梯度下降：

$$\mathcal{L}_{\text{opt}} = \underbrace{\sum_{net} \text{WA}(net)}_{\text{加权平均线长（HPWL 的光滑近似）}} + \lambda \underbrace{\sum_{bin} (\rho_{bin} - \rho_{target})^2}_{\text{密度惩罚（电场/泊松方程法）}} + \mu \underbrace{\sum \text{ConstraintPenalty}}_{\text{软约束}}$$

- **WA（Weighted-Average）线长模型**：$\text{HPWL}$ 不可微，用 log-sum-exp 或 WA 平滑
- **密度惩罚**：ePlace 的静电场类比方法，把器件看作电荷，用泊松方程求解，梯度即"电场力"，物理上很优雅且效果好
- 固定器件的坐标梯度置零
- 旋转与面在这一阶段保持不变（离散量交给 RL 决定）

这一步通常能在 RL 结果基础上把 HPWL 再降 10~20%，且几乎不改变整体布局结构（工程师看到的还是他认可的那个方案）。

---

## 8. 阶段 4：合法化与规则修复

```
1. 消重叠（Legalization）
   - 器件按面积降序，依次找最近合法位置（Tetris-like 或最近邻搜索）
   - 大器件优先保持原位，小器件让路
2. 网格对齐
   - 对齐到设计网格（如 0.05mm），旋转规整化
   - 同类器件对齐成行/列（工程师非常在意的"整齐度"）
3. 规则引擎全量检查
4. 局部修复
   - 违反项 → 提取局部子问题 → CP-SAT 精确求解或局部搜索
   - 无法修复的标记为"需人工处理"并给出说明
5. 输出前置校验：硬约束违反必须为 0，否则不允许输出
```

## 9. 阶段 5：评估、排序与解释

### 9.1 多方案生成
通过不同的随机种子、不同的目标权重、不同的模块顺序，生成 3~5 个候选方案，覆盖不同权衡（如"最短线长版"、"最优散热版"、"最贴近历史风格版"）。

### 9.2 解释生成
每条建议附带解释，这是工程师接受度的关键。解释来源于三处：
1. **规则引用**：`"C112 放在此处是因为《布局规范 v3.2》5.3.2 要求去耦电容距电源引脚 ≤ 5mm"`
2. **指标改善**：`"该方案相比初始位置，DDR 数据组总线长缩短 18%，拥塞峰值下降 12%"`
3. **历史类比**：`"该 DDR 区域布局参考了项目 XX-2024-017 的同类设计（相似度 0.87）"`

用 LLM 把结构化的解释信息组织成自然语言。**注意：解释必须由真实计算结果驱动，绝不能让 LLM 编造理由。**

### 9.3 评价指标体系

| 类别 | 指标 | 说明 |
|---|---|---|
| 合法性 | 硬约束违反数 | 必须 = 0 |
| 质量 | HPWL、加权 HPWL（关键网络加权） | 与人类布局对比 |
| 质量 | 拥塞峰值 / 平均拥塞 | |
| 质量 | 布线后真实总长、过孔数、DRC 数 | 需实际跑布线，抽样验证 |
| 质量 | 热点最高温度 / 温度方差 | 抽样跑热仿真验证 |
| 规范 | 软规则违反数、加权违分 | |
| 人类对齐 | 与人类布局的位置相似度（匈牙利匹配后的平均位移） | |
| 人类对齐 | 分区一致性 IoU | |
| 人类对齐 | **专家主观评分（1~5）** | 最终裁决 |
| 落地 | **工程师采纳率** | 最重要的业务指标 |

## 11. 关键参考工作及其对我们的启示

| 工作 | 核心思想 | 对我们的启示 | 需注意的差异 |
|---|---|---|---|
| **Mirhoseini et al., Nature 2021**（Google 芯片布局） | Edge-GNN 编码 + PPO，宏单元序列摆放，GNN 价值网络作奖励代理 | 整体框架可借鉴；GNN + RL 结合的范式来源 | 只处理宏单元；标准单元用力导向；PCB 器件异构性远大于宏单元 |
| **MaskPlace (NeurIPS 2022)** | 全像素视觉表示 + 密集动作掩码，避免重叠 | **动作掩码机制直接可用**；视觉表示与图表示互补的思想 | 纯 CNN，缺少图结构泛化能力 |
| **ChiPFormer (ICML 2023)** | 离线 RL + Decision Transformer，跨电路迁移 | **最贴合我们"有历史数据、无好仿真器"的处境** | 需要构造离线数据集的回报标注 |
| **DREAMPlace** | 把布局写成可微目标，GPU 加速梯度优化 | **阶段 3 直接借鉴** | 面向 IC 标准单元，需改造 |
| **ePlace / RePlAce** | 静电场密度惩罚模型 | 密度项的数学形式 | 同上 |
| **GraphPlanner** | VAE + GNN 一次性生成布局 | 顺序无关建模的备选路线 | 生成质量不如序列决策 |
| **RLHF / Bradley-Terry 偏好学习** | 从人类偏好学奖励模型 | **解决多目标权重与主观审美的核心手段** | 需要专家投入标注 |
| **InstaDeep DeepPCB** | RL 做 PCB 自动布线 | 证明 RL 在 PCB 域可行 | 是布线不是布局 |

## 12. 最容易踩的坑（提前警示）

1. **代理评估器与真实质量不相关** → RL 优化出"刷分布局"。**必须先做校准，再训练。**
2. **忽略摆放顺序问题** → BC 数据构造错误，模型学到混乱的顺序先验。
3. **大网络（GND/VCC）污染图表示** → 所有器件嵌入趋同。必须特殊处理。
4. **只用 HPWL 做奖励** → 器件挤成一坨，工程师完全不能用。密度/拥塞项必须同时在。
5. **硬约束靠奖励惩罚** → 偶尔违反，工程师直接失去信任。**必须用掩码机制。**
6. **训练集包含低质量历史板** → 模型学会烂布局。必须做设计质量分级。
7. **没有专家深度参与** → 做出来的东西自己觉得挺好，工程师说没法用。**SME 必须从第一天就在项目组里。**
8. **一开始就追求全板端到端** → 6 个月一事无成。**从模块级、小规模开始。**
9. **RL 训练环境采样太慢** → 训练周期以月计。评估器性能是第一优先级工程问题。
10. **忘了"可撤销"** → 工程师不敢点"应用建议"。写回 Allegro 必须支持完整 undo。

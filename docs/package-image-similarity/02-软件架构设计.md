## 1. 架构总览

本模块是 PCB-Copilot **相似设计复用**链路中的「封装形态匹配」子系统，采用**分层 + 可插拔相似度引擎**设计：

```
┌─────────────────────────────────────────────────────────────────┐
│  Agent / 对话层                                                  │
│  find_similar_packages(json) → project_code/refdes + bbox         │
└────────────────────────────┬────────────────────────────────────┘
                             │
┌────────────────────────────▼────────────────────────────────────┐
│  检索编排层                                                      │
│  pin_count 硬过滤 → 读 fpgeom → 几何 IoU 精排 → Top-K            │
└─────┬──────────────────────────────────┬──────────────────────────┘
      │                                  │
      ▼                                  ▼
┌─────────────────┐              ┌──────────────────────┐
│ MySQL           │              │ 几何引擎              │
│ footprint_library│              │ fpgeom + Shapely IoU │
│ 元数据 + fpgeom  │              │ best_geom_iou()      │
└─────────────────┘              └──────────────────────┘
      ▲
      │ 入库：POST /library → UPSERT
┌─────┴───────────────────────────────────────────────────────────┐
│  HTTP 入库（唯一入口）                                            │
│  api_app.import_to_library → footprint_db.upsert_footprint()   │
└─────────────────────────────────────────────────────────────────┘
```

**设计原则（v0.4）**：

1. **fpgeom 为比对中间格式**：文件（`.fpgeom`）与数据库（LONGBLOB）同格式。
2. **IoU 不入库**：候选集随 query 变化，算法可升级。
3. **pin_count 索引硬过滤**：SQL + 应用双层校验。
4. **不拆 JSON 多表**：检索热路径只读 fpgeom blob。

## 3. 图像预处理流水线

Allegro 导出的封装预览图具有共同特点（1190967 样本实测）：

- 分辨率统一：**1270 × 632**，RGB
- 深色背景 + 浅色焊盘/丝印，颜色种类少（unique 灰度级 ≤ 36）
- 四张图文件大小相同，说明导出模板一致 → **有利于 SSIM，但也导致跨封装 SSIM 偏高**

### 3.1 标准预处理步骤

```
原始 BMP/PNG
    → 转灰度
    → 可选：自动裁剪内容区（去均匀黑边，按非零像素 bounding box）
    → 缩放到固定短边（如 256px），保持宽高比，居中 pad
    → 二值化（阈值 ~30/255，焊盘为白）
    → 可选：形态学开运算去噪点
    → 输出：gray_tensor, binary_tensor
```

**旋转归一化（Phase 2）**：对 binary 图计算最小外接矩形主方向，旋转至水平；或对 4 个 90° 旋转各算相似度取 max。

### 3.2 为何必须预处理

| 问题 | 不预处理 | 预处理后 |
|---|---|---|
| 导出尺寸不同 | SSIM 需 resize，形变 | 统一 scale |
| 黑边占比不同 | 背景主导 SSIM | 裁剪后焊盘占比稳定 |
| 线宽抖动 | 特征点不稳定 | 二值化缓解 |

## 4. 相似度算法设计

### 4.1 算法接口

```python
class SimilarityMetric(ABC):
    name: str

    @abstractmethod
    def compare(self, img_a: PreprocessedImage, img_b: PreprocessedImage) -> float:
        """返回 [0, 1]，越大越相似"""
        ...
```

所有 metric 对**已预处理**图像操作，避免重复逻辑。

### 4.2 SSIM（基线）

- **库**：`scikit-image.metrics.structural_similarity`
- **输入**：灰度图，`data_range=255`
- **优点**：实现成熟；对轻微压缩/亮度变化稳健
- **缺点**（1190967 实测）：BGA vs WSON 仍有 **~0.43**，QFP vs QFN **~0.59**，区分度不足

```
          bga1088   qfn88   qfp128   wson8
bga1088   1.000    0.642   0.572    0.428
qfn88     0.642    1.000   0.595    0.469
qfp128    0.572    0.595   1.000    0.545
wson8     0.428    0.469   0.545    1.000
```

**结论**：SSIM 适合作为**辅助信号**，不适合单独决策。

### 4.3 ORB 特征匹配（推荐）

- **库**：OpenCV `cv2.ORB_create` + `BFMatcher`
- **流程**：灰度图提 ORB → 交叉匹配 → 距离 < 阈值的 good matches → `score = |good| / max(|kp1|, |kp2|)`
- **1190967 实测**（ratio）：

| 对比 | ORB ratio | 解读 |
|---|---|---|
| qfp128 vs qfn88 | **0.050** | 同族（四边引脚）最高 |
| qfp128 vs wson8 | 0.048 | 次之 |
| bga1088 vs wson8 | 0.003 | 跨族最低 |

- **优点**：对局部几何（焊盘排列）更敏感；开源、无专利问题（ORB）
- **缺点**：单对比计算比 SSIM 慢；特征少的小封装（WSON8）不稳定

### 4.4 Hu 矩形状描述（轻量）

- **输入**：二值化焊盘图
- **方法**：`cv2.moments` → `cv2.HuMoments`，log 变换后欧氏距离 → 映射到 [0,1]
- **实测**：qfn88 vs qfp128 = **0.243**，其余对 ~0.04
- **优点**：极快；对全局轮廓有效
- **缺点**：对称封装易混淆；对焊盘数量细节不敏感

### 4.5 感知哈希 pHash（不推荐作主指标）

- **用途**：判断「是否同一张图 / 近重复导出」
- **不适用于**：「哪张封装更相似」的细粒度排序
- 可作为导入去重（同一 `packageSymbol` 多次导出）

### 4.6 深度嵌入 CLIP / Siamese（Phase 2）

| 方案 | 开源参考 | 适用判断 |
|---|---|---|
| CLIP (ViT-B/32) | OpenCLIP, HuggingFace | 语义级；QFN/QFP 可能.embedding 过近 |
| Siamese + Triplet | PyTorch 教程、[PicTrace](https://github.com/Solrikk/PicTrace) | 需标注「同/异封装对」；小样本可微调 |
| 自监督 ResNet 嵌入 | timm + FAISS | 无标注时用 ImageNet 预训练特征 |

**建议**：有 ≥500 对工程师标注后再上；之前用 **[jingwora/Image-Comparison](https://github.com/jingwora/Image-Comparison)** 作方法对照基准。

### 4.7 几何 IoU（当前主路径，v0.4）

1. JSON → 铜箔多边形（`footprint_json.py`）
2. 尺寸归一 → **fpgeom**（`fpgeom.py`）
3. 入库 MySQL LONGBLOB 或本地 `.fpgeom` 文件
4. 比对：`shapely` 精确 intersection/union，B 试 4 个 90° 旋转
5. **无栅格化、无 grid 参数**

## 5.1 处理流程（检索）

```
输入: query_json
  │
  ├─1─► build_fpgeom_from_footprint(query)
  │
  ├─2─► SQL: SELECT ... FROM footprint_library WHERE pin_count = ?
  │
  ├─3─► 对每条 candidate.fpgeom 调用 best_geom_iou()
  │
  └─4─► ORDER BY iou DESC LIMIT top_k
```

## 6. MySQL 表设计（v0.9.2）

```sql
footprint_library (
  id, name, pin_count, units,
  bbox_min_x/y, bbox_max_x/y,
  fpgeom_version, fpgeom LONGBLOB,
  project_code, refdes,
  source_file, source_json JSON, warnings JSON,
  geom_islands, created_at, updated_at
)
-- 唯一键: (project_code, refdes)
-- 索引: pin_count, name, project_code
```

| 决策 | 理由 |
|---|---|
| fpgeom BYTEA 而非拆 pins 表 | 比对热路径一次读出即可 |
| source_json JSONB 归档 | Agent 溯源、字段升级重算 |
| IoU 不入库 | 算法迭代无需刷库 |
| content_hash 去重 | 同一 JSON 不重复存 |

脚本：`scripts/footprint_db/`（见 README）

## 9. 测试策略

### 9.1 单元测试

- 同一图像自比：所有 metric → 1.0（或 >0.99）
- 预处理确定性：同输入字节级相同输出
- `pin_match` 边界：相等、差 50%、差 51%

### 9.2 样本集回归（1190967）

**期望排序直觉**（query = qfn88）：

1. qfp128（同四边引脚族，引脚数 closer than bga）
2. wson8
3. bga1088

**期望**（query = wson8）：与其他三者相似度均较低。

记录 baseline 分数表，算法变更需 diff 对比。

## 10. 架构决策记录（ADR）

| ID | 决策 | 理由 |
|---|---|---|
| ADR-01 | MVP 用 Hybrid（SSIM+ORB+Hu），不用纯 CLIP | 样本少、形态差异细、CLIP 易语义过拟合 |
| ADR-02 | 综合排序在编排层做，不进 metric | 分离「形态像」与「业务权重」 |
| ADR-03 | 几何 JSON 为主、位图为辅 | 1190967 实测 SSIM 区分度不足；设计部 JSON 已定稿 |
| ADR-08 | shapes 用 `[{shape,void}]` 数组 | void 从属于外轮廓岛，结构更清晰 |
| ADR-09 | 检索：硬过滤后 IoU 精排 | 与 tscircuit / 工程师习惯一致 |
| ADR-06 | voids 与 shapes 平级（旧格式） | 加载器仍兼容，自动归一 |
| ADR-07 | 文档随字段变更同步更新 PRD/架构/进度 | 设计部协作约定 |
| ADR-04 | 不做 diff 可视化 | 产品明确不需要，降低 scope |
| ADR-10 | MySQL + fpgeom LONGBLOB | PoC 选型；唯一键 project_code+refdes |
| ADR-11 | IoU 不入库 | 算法可升级；避免 N² 存储 |
| ADR-12 | 不拆 JSON 多表 | 检索场景 fpgeom 足够 |

# 前端检索服务接口开发设计文档

## 1. 接口概览

| 项目 | 说明 |
| --- | --- |
| 服务模块 | PCB 对话检索 + PDF 预览（`search_service`） |
| 推荐调用前缀 | `{{apiBase}}`（示例 `http://192.168.12.16:8000`） |
| 协议 | HTTP/HTTPS |
| JSON 响应 | `application/json`（UTF-8） |
| 文件响应 | `application/pdf`、`image/png`、`application/octet-stream` |
| 前端工程 | 仓库 `DAY002/desktop` |
| 在线文档 | `{{apiBase}}/docs` |

## 2. 环境变量（前端 / Postman）

| 变量名 | 示例值 | 说明 |
| --- | --- | --- |
| `apiBase` | `http://192.168.12.16:8000` | 检索服务根地址，**不含** `/api` 后缀 |
| `sessionId` | `20260915003000-a1b2c3d4` | 上传 JSON 后返回的会话 ID |
| `projectCode` | `1165551` | 项目编码 |
| `topSide` | `true` | 板面路径段：`true`=正面 / `false`=背面（JSON 字段 `top_side` 为 boolean） |
| `refdes` | `U4` | 位号 |

## 3. 公共约定

### 3.1 成功与失败

- 多数接口成功时 **HTTP 200**，Body 为 JSON 对象。
- 业务失败常见：`{"ok": false, "message": "原因说明", ...}`，HTTP 可能为 400 / 404 / 502。
- 前端 `api.js` 使用 axios：`baseURL = apiBase`，路径以 `/api/...` 开头。

### 3.2 相对 URL

响应中的 `preview_url`、`file_url`、`clip_url` 等多为 **以 `/api` 开头的相对路径**，展示时需拼接：

```text
{{apiBase}}{{preview_url}}
```

### 3.3 板级 PDF 如何唯一确定

入库表 `project_pdf` 以 **`project_code` + `top_side`** 唯一约束一份板级 PDF。  
- **库内**：`top_side` 为 `TINYINT(1)`，`1`=正面、`0`=反面。  
- **JSON 响应**：`top_side` 为 **boolean**（`true` 正面 / `false` 反面）。  
- **URL 路径**：第二段为字面量 **`true` 或 `false`**，例如 `/api/pdf/1165551/true/preview`。  
板级 PDF **仅一页**，接口不再使用 `page_no` / `page_count`。

明工/设计 JSON 入库字段 `top_side`（或 `topSide`）：**boolean 或 0|1**（与《封装形状还原》一致）；服务端入库前统一转为布尔再写入 MySQL。

### 3.4 请求参数字段表约定

除特别说明外，下表列含义为：

| 列名 | 含义 |
| --- | --- |
| 参数名 | Query / Path / Form 名称 |
| 位置 | `Query` / `Path` / `Form` |
| 类型 | JSON 类型或 HTTP 原始类型（如 `file[]`） |
| 是否必填 | 是 / 否 |
| 示例 | Postman 示例值 |
| 说明 | 业务含义 |

### 4.2 上传当前板 JSON（创建会话）

| 项目 | 说明 |
| --- | --- |
| 接口名称 | 上传 JSON 创建会话 |
| Method | POST |
| URL | `{{apiBase}}/api/agent/sessions` |
| Content-Type | `multipart/form-data` |
| 作用 | 格式校验 + 写入服务端会话目录，**不入 MySQL** |

#### Form 字段

| 参数名 | 位置 | 类型 | 是否必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `files` | Form | file[] | 是 | `1165551_U4.json` | 一个或多个器件 JSON；字段名必须为 `files` |

#### 请求 URL 示例

```text
POST {{apiBase}}/api/agent/sessions
Body: form-data  files=@1165551_D3.json  files=@1165551_U4.json
```

#### 成功响应示例

```json
{
  "session_id": "20260915003000-a1b2c3d4",
  "component_count": 2,
  "refdes_list": ["D3", "U4"]
}
```

#### 返回字段说明

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `session_id` | string | 后续对话必填 |
| `component_count` | number | 通过校验的器件数 |
| `refdes_list` | string[] | 位号列表 |

#### 异常响应

| HTTP 状态码 | 响应体示例 | 触发条件 |
| --- | --- | --- |
| 400 | `{"ok": false, "message": "pins[0] 缺少 padstack", "errors": [{"file": "U1.json", "error": "..."}]}` | JSON 格式不合格 |
| 400 | `{"ok": false, "message": "请上传至少一个 JSON 文件"}` | 未传文件 |

### 4.5 对话检索

| 项目 | 说明 |
| --- | --- |
| 接口名称 | 对话检索 |
| Method | POST |
| URL | `{{apiBase}}/api/agent/chat` |
| Content-Type | `multipart/form-data` |
| 作用 | 解析位号 → IoU 形态召回 → LLM 排序 → 返回推荐列表 + PDF 链接 |

| 参数名 | 位置 | 类型 | 是否必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- |


#### 返回字段说明（主要）

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `reply` | string | 展示文案 |
| `clarification` | string \| null | 非空时需用户补充说明 |
| `target_refdes` | string | 解析出的目标位号 |
| `return_count` | number | `items` 条数 |
| `similar.results` | array | IoU Top-K（前端可开关展示） |
| `items` | array | LLM 排序后的推荐结果 |
| `items[].pdf` | object | PDF 元数据与相对 URL（含 `project_code`、`top_side` boolean） |
| `items[].pdf.top_side` | boolean | `true` 正面 / `false` 反面 |
| `response_ms` | number | 服务端耗时（毫秒） |

#### 异常响应

| HTTP 状态码 | 响应体示例 | 触发条件 |
| --- | --- | --- |
| 400 | `{"ok": false, "message": "请输入检索内容"}` | `message` 为空 |
| 404 | `{"ok": false, "message": "会话不存在：xxx"}` | 无效 `session_id` |
| 200/500 | `{"message": "LLM 未启用或调用失败..."}` | 配置 `llm.enabled=false` 或模型错误 |

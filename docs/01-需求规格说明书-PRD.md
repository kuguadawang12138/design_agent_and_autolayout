## 1. 项目背景与目标

### 1.1 现状痛点

1. **设计规范散落**：规范以 Word / PDF / Excel / PPT / EDA 导出报告等多种形式存在，工程师查不到、查不准、不知道有没有更新版本，新人上手周期长。
2. **规范执行靠人**：大量规范无法被 Allegro Constraint Manager 表达（尤其是布局类、经验类），只能靠评审会人工检查，漏检率高且评审成本大。
3. **布局高度依赖经验**：布局是最耗时、最影响质量的环节，资深工程师经验难以沉淀与复用，新人做的布局需要反复返工。

### 1.2 项目目标

| 层级 | 目标 |
|---|---|
| 短期（0~3 月） | 建成**设计规范知识库问答系统**，工程师能用自然语言问出准确、可溯源的规范答案 |
| 中期（3~5 月） | 建成**可执行规则引擎**，能对 Allegro 设计做超出 DRC 范围的自动化规范符合性检查 |
| 长期（4~6 月 PoC，后续持续） | 建成**GNN + RL 辅助布局引擎**，对模块级布局给出可采纳的位置与分区建议 |

### 1.3 明确的非目标（PoC 阶段不做）

- 不做自动布线（Auto-routing）
- 不做全板一键自动布局（只做"给建议"，最终决策权在工程师）
- 不做 SI/PI 仿真替代（可调用，不自研）
- 不做原理图自动生成

## 2. 用户与场景

### 2.1 用户角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| **PCB Layout 工程师** | 主要用户，日常在 Allegro 内工作 | 快速查规范、快速自检、布局提效 |
| **硬件（原理图）工程师** | 提供网表与约束 | 查规范、查选型要求 |
| **SI/PI 工程师** | 高速信号负责人 | 高速约束规范、布局对 SI 的影响 |
| **设计评审专家 / 技术委员会** | 评审与规范维护者 | 规范的版本管理、检查报告、评审辅助 |
| **新人工程师** | 培训对象 | 学习规范、理解"为什么" |
| **算法工程师（内部）** | 系统维护方 | 数据管道、模型迭代、评测 |

### 2.2 典型场景

**S1 — 规范速查（高频）**
工程师在做 DDR4 布局时想确认等长要求：
> 问："DDR4 数据组的等长偏差要求是多少？参考平面有什么要求？"
> 系统答：给出具体数值 + 出处（《高速设计规范 v3.2》第 4.2.1 节）+ 原文截图 + 相关联的其他条款。

**S2 — 规范符合性自检（中频，价值极高）**
工程师完成布局后，在 Allegro 插件里点"规范检查"：
> 系统输出：违反项列表（如"U7 的 0.1uF 去耦电容 C112 距离电源引脚 8.3mm，超出规范 5mm 要求"），可点击直接在 Allegro 中高亮定位。

**S3 — 布局建议（本项目的技术制高点）**
工程师导入网表、板框、结构约束后：
> 系统输出：① 功能分区（Room）划分建议 ② 关键器件（主控、电源、连接器、DDR）位置建议 ③ 外围小器件摆放建议 ④ 每条建议的理由与相关规范引用 ⑤ 量化评分（线长、拥塞、热、规范违反）。工程师可整体采纳、部分采纳或忽略。

**S4 — 相似设计复用（最易落地，建议优先做）**
> 问："历史上有没有做过基于 XX 主控 + LPDDR4 的板子？它的 DDR 区域怎么布的？"
> 系统答：召回 Top-N 相似历史板，展示其布局截图与关键参数，支持将该模块布局作为模板套用到当前设计。

**S5 — 评审辅助**
评审前自动生成《设计规范符合性报告》，评审会聚焦于系统无法判定的主观问题。

## 3. 功能需求

### 3.1 模块一：设计规范知识库与检索问答（P0，首期落地）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| KB-01 | 多格式文档接入：PDF / Word / Excel / PPT / Visio / Markdown / EDA 导出报告 / 扫描件 | P0 | 支持列出的全部格式，扫描件 OCR 准确率 ≥ 95% |
| KB-02 | 版式解析：保留标题层级、表格结构、图片、公式 | P0 | 表格还原准确率 ≥ 90%（规范里大量数值在表格中，这是准确率的生命线） |
| KB-03 | 文档分块（Chunking）：按标题层级 + 语义边界切分，保留上下文 | P0 | 单块可独立回答问题的比例 ≥ 85% |
| KB-04 | 混合检索：向量检索 + 关键词（BM25）检索 + 重排 | P0 | Top-5 召回率 ≥ 92% |
| KB-05 | 生成式问答：基于检索结果生成答案，**必须带引用溯源** | P0 | 每个答案标注来源文档、章节、页码，可一键跳原文 |
| KB-06 | 拒答机制：知识库无相关内容时明确说"未找到"，禁止编造 | P0 | 无依据编造率 < 2% |
| KB-07 | 多轮对话：支持追问、指代消解 | P1 | — |
| KB-08 | 术语与同义词库：PCB 领域缩写扩展（如 CM ↔ Constraint Manager、去耦 ↔ 退耦 ↔ Decoupling） | P0 | 领域词表 ≥ 500 条 |
| KB-09 | 权限与密级：按项目/部门/密级控制可见范围 | P0 | 越权访问为 0 |
| KB-10 | 文档版本管理：规范更新后旧版本自动失效或标注，答案标明版本 | P0 | 答案不引用已废止版本 |
| KB-11 | 反馈闭环：工程师可对答案打分/纠错，进入标注队列 | P1 | — |
| KB-12 | 图片理解：规范中的示意图（正确/错误布局对比图）能被检索并展示 | P1 | 图文混排答案 |
| KB-13 | 知识图谱：规范条款之间的引用、约束、冲突关系可视化 | P2 | — |

**关键设计决策**：知识库入库时必须完成 **L1/L2/L3 分类打标**（见 `00-业务基础与术语表.md` 第四章），因为 L1 条款要同时流向规则引擎，L2 条款要流向布局评分函数。

### 3.3 模块三：AI 辅助布局（P0 战略级，PoC 目标为模块级建议）

| PL-10 | 量化评分：HPWL、拥塞、规则违反数、热分布、对称性 | P0 | 指标可与人类布局对比 |

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 历史 `.brd` 数据无法批量自动化提取 | 中 | **致命**（布局模型无米下锅） | **第 1 个月必须完成数据提取管道验证**，若不通则退回 IPC-2581 / Extracta 方案 |
| 历史设计质量参差，脏数据污染模型 | 高 | 高 | 建立设计质量分级，只用"已量产 + 无重大问题"的板做训练 |
| 规范文档表格解析不准，导致答案数值错误 | 高 | 高 | 表格单独走结构化抽取路径 + 数值型答案强制人工校验入库 |
| 工程师不信任 AI 建议，拒绝使用 | 中 | 高 | 全程"给建议不替决策"；建议必带解释；早期深度绑定 2~3 位资深工程师做共创 |
| RL 训练无法收敛 / 效果不及人类 | **高** | 中 | **必须先做模仿学习 + 检索复用兜底**，RL 作为增强而非唯一路径；即使 RL 失败，L2/L3 交付物仍有价值 |
| 6 个月同时做三大模块，资源不足 | 高 | 高 | 严格按 M1 知识库 → M2 规则引擎 → M3 布局 的顺序滚动交付，每阶段有独立可用产物 |
| 内网无法下载开源模型/依赖 | 中 | 中 | 提前建立离线模型仓库与私有 PyPI 镜像 |

## 8. 依赖与前提条件

1. 获取 Allegro SKILL 开发文档与授权，确认可用的 API 范围。
2. 获取历史设计项目的批量访问权限（PDM / 文件服务器）。
3. 指定 2~3 位资深 PCB 工程师作为**领域专家（SME）**，投入 ≥ 30% 工时参与规范梳理、标注与评审。
4. GPU 服务器资源分配到位（训练与推理分离）。
5. 内网离线模型仓库、私有软件源建设完成。
6. 数据脱敏与安全合规方案通过信息安全评审。

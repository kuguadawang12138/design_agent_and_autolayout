## 一、总体节奏

三条线并行，但**资源投入的重心是滚动前移**的：

```
月份      M1      M2      M3      M4      M5      M6
        ├───────┼───────┼───────┼───────┼───────┼───────┤
数据线  ████████████████████████░░░░░░░░░░░░░░░░░░░░░░░░
知识库  ░░██████████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░  ← M3 末上线
规则引擎        ░░░░████████████████████░░░░░░░░░░░░░░░░  ← M5 中上线
布局线          ░░░░░░░░████████████████████████████████  ← M6 末 Demo
集成/插件               ░░░░░░░░░░░░████████████████████
```

关键判断：**先做知识工程，再做算法**。理由：
1. 你首期最想落地的就是规范检索问答，它 3 个月能出成果，能尽早验证文档解析与检索链路，并为规则引擎沉淀规则来源。
2. 规则引擎的规则来自规范梳理，布局的评价标准来自规则，存在硬依赖。
3. 数据管道建设（尤其 `.brd` 提取）需要时间，正好与知识库开发并行。
4. 但**数据线必须从第 1 天就全力开跑**，它是布局线的前置。

## 二、里程碑详解

### M1（第 1 个月）：地基与验证

**主题：把最大的技术风险在第一个月内暴露掉**

| 工作项 | 负责 | 交付物 |
|---|---|---|
| 数据资产盘点 | 产品 + SME | 盘点清单表 |
| **Allegro 数据提取可行性验证** | 算法 + EDA 管理员 | **10 块板成功提取为 PDM，可行性报告** |
| **SKILL 插件通信可行性验证** | 工程 | Allegro 内点按钮调用外部服务的最小 Demo |
| 规范文档解析引擎选型对比 | 算法 | 20 份真实规范多引擎对比报告 |
| 基础设施搭建 | 运维 | 内网 GitLab、私有 PyPI、Harbor、GPU 环境、K8s/Compose |
| L1/L2/L3 规范分类体系定稿 | SME + 算法 | 分类标准文档 + 100 条样例 |

**M1 决策关卡（Go/No-Go）**：
- ✅ `.brd` 能否批量结构化提取？→ 不能则布局线降级为"仅基于新设计的增量数据"或改用 IPC-2581
- ✅ SKILL 能否与外部服务通信？→ 不能则插件形态改为文件交换 + 独立客户端
- ✅ 规范解析准确率是否可接受？→ 不行则关键规范人工结构化录入

## 三、关键技术能力

| 能力方向 | 主要内容 | 关键期 |
|---|---|---|
| **算法（RL/GNN）** | 图建模、GNN、RL、评估器、训练 | M3~M6 |
| 算法（NLP/RAG） | 文档解析、检索、问答、规则抽取 | M1~M4 |
| **数据工程** | EDA 数据提取、管道、特征、数据集 | **M1~M4（前期最关键）** |
| 后端工程 | API、服务、规则引擎、任务调度 | 全程 |
| 前端工程 | Web 控制台、可视化、标注平台 | M2~M6 |
| **EDA 集成（SKILL）** | Allegro 插件、本地代理、数据接口 | M1、M4~M6 |
| 运维 / MLOps | 基础设施、GPU、部署、监控 | M1、持续 |
| **PCB 领域知识（SME）** | 规范梳理、规则确认、标注、评审 | **全程，不可缺席** |

> **最容易被低估的两个技术环节**：EDA 数据提取（比想象中难得多）和 SKILL 集成（小众技能，资料少）。这两块建议在 M1 就做最小可行验证。

## 五、阶段性技术产出

即使布局线（最难的部分）延期或失败，项目在每个阶段都有独立可用的技术产物：

| 阶段 | 独立产物 | 即使后续失败也保留 |
|---|---|---|
| M3 | 规范知识库问答 | ✅ 直接提升规范查询效率 |
| M4 | 历史模块布局复用库 | ✅ 可复用模块库，本身就是知识资产 |
| M5 | 规则引擎自动检查 | ✅ 替代大量人工评审，减少设计缺陷 |
| M6 | AI 辅助布局建议 | 最终目标 |

**每个阶段都要有独立可用的产物**，把大工程的技术风险拆解成可验证的阶段性目标。
